# 7. W5500 Ethernet controller

This document describes the W5500 as this firmware uses it: the SPI framing
and port, reset and identification, socket buffer allocation, the registers
and socket states the link relies on, the chip features deliberately left
unused, and the vendored WIZnet library with its one local modification. The
Modbus protocol and the link state machine that run on top of it are in
[08-modbus-tcp.md](08-modbus-tcp.md).

**Source files:** `Lib/w5500/w5500_stm32.c`, `Lib/w5500/w5500_stm32.h`,
`Lib/w5500/CMakeLists.txt`, `Lib/w5500/UPSTREAM.md`,
`Lib/w5500/ioLibrary/Ethernet/`, `App/Src/plc_link.c` (`chip_bring_up()`),
`App/Inc/plc_config.h`, `Core/Src/spi.c`.

## 7.1 Why the W5500

The STM32F103 has no Ethernet MAC and only 20 KB of RAM, too little to host a
software TCP/IP stack comfortably. The W5500 integrates MAC, PHY and a
hardwired TCP/IP stack with 32 KB of packet buffer; the MCU exchanges only
application payload with it over SPI. The chip supports eight hardware
sockets; this firmware uses one.

## 7.2 Wiring and SPI

| Signal | MCU pin | Notes |
|---|---|---|
| SCLK | PB13 (SPI2_SCK) | 12 Mbit/s |
| MISO | PB14 (SPI2_MISO) | module → MCU |
| MOSI | PB15 (SPI2_MOSI) | MCU → module |
| SCSn | PB12 (`ETH_NSS`) | GPIO, driven by software, active low, boots high |
| RSTn | PA10 (`ETH_RESET`) | GPIO, active low, boots high |
| INTn | PB5 (`ETH_INT`) | EXTI falling edge, pull-up; never asserted (section 7.6) |
| 3V3, GND | 3.3 V rail | |

SPI2 runs in master mode 0 (CPOL 0, CPHA first edge), MSB first, 8-bit,
prescaler ÷2 from the 24 MHz APB1 clock = 12 Mbit/s. On long jumper wires a
prescaler of ÷4 (6 Mbit/s) is the first thing to try if transfers are
unreliable; it is a one-line change in the `.ioc`.

The library is built with `_WIZCHIP_IO_MODE_ = _WIZCHIP_IO_MODE_SPI_VDM_`
(variable-length data mode): every access is one SPI frame of a 16-bit
address, a control byte (block select, read/write, operation mode 00) and the
data, with SCSn held low for the whole frame. VDM is what lets one SCSn
assertion carry a burst of any length.

## 7.3 The STM32 port — `w5500_stm32.c`

The WIZnet library calls out through registered function pointers.
`w5500_stm32_init(SPI_HandleTypeDef *hspi)` deselects the chip and registers:

| ioLibrary hook | Port function | Implementation |
|---|---|---|
| `reg_wizchip_cs_cbfunc` | `w5500_cs_select()` / `w5500_cs_deselect()` | `HAL_GPIO_WritePin(ETH_NSS…)` low / high |
| `reg_wizchip_spi_cbfunc` | `w5500_read_byte()` / `w5500_write_byte()` | one-byte bursts |
| `reg_wizchip_spiburst_cbfunc` | `w5500_read_burst()` / `w5500_write_burst()` | `HAL_SPI_TransmitReceive()` with a buffer pre-filled with `0xFF` / `HAL_SPI_Transmit()` |
| `reg_wizchip_cris_cbfunc` | `w5500_cris_enter()` / `w5500_cris_exit()` | empty |

The burst callbacks matter for speed: every register access in the library is
a burst, and without them each byte would be a separate HAL call. Each transfer
has a `W5500_SPI_TIMEOUT_MS` (100 ms) timeout; a healthy transfer takes
microseconds, so hitting it means the bus is stuck. HAL return codes are not
checked: a failed transfer surfaces as wrong data, which the `VERSIONR` check
and the socket state checks catch.

The critical-section hooks are empty because SPI2 is only ever used from
`plc_link_tick()` in the main loop; no interrupt touches the bus. Masking
interrupts there would add jitter to the STEP timers for no benefit. If a
future change touches the W5500 from an ISR, these hooks must mask interrupts.

`w5500_stm32_hard_reset()` drives RSTn low for `PLC_W5500_RESET_LOW_MS`
(2 ms; the datasheet minimum is 500 µs), releases it and waits
`PLC_W5500_BOOT_MS` (10 ms) for the PLL to settle.

The port includes `main.h` (for the `ETH_*` pin macros) and `plc_config.h`
(for the reset timings), which is why `Lib/w5500/CMakeLists.txt` adds
`App/Inc` and `Core/Inc` to its private include path.

## 7.4 Bring-up — `chip_bring_up()`

Called from `plc_link_init()` and from every retry in the `CHIP_FAULT` state:

1. `w5500_stm32_hard_reset()` then `w5500_stm32_init()`.
2. **Identification:** `getVERSIONR()` must return `PLC_W5500_VERSION`
   (`0x04`). Every W5500 reads this value, so a single register read proves
   chip select, clock polarity, bit order and the four SPI wires at once.
   Any other value aborts bring-up.
3. **Buffers:** `wizchip_init(tx_sizes, rx_sizes)` gives socket 0 all
   16 KB of TX and all 16 KB of RX memory (`PLC_SOCKET_BUFFER_KB`); sockets 1–7
   get 0. A 12-byte request and an 11-byte response would fit the smallest
   allocation; there is simply nothing else to spend it on.
4. **Identity:** `wizchip_setnetinfo()` with the static MAC, IP, subnet mask
   and gateway from `plc_config.h` (`NETINFO_STATIC`; there is no DHCP
   client). The DNS field is set to the gateway and is unused.

## 7.5 What the link relies on at run time

| Chip facility | Library call | Used for |
|---|---|---|
| PHY link status (PHYCFGR.LNK) | `wizphy_getphylink()` | `LINK_WAIT` waits for `PHY_LINK_ON` before opening a socket |
| Socket open, TCP, non-blocking | `socket(0, Sn_MR_TCP, PLC_LOCAL_PORT, SF_IO_NONBLOCK)` | must return 0 |
| Active open | `connect(0, server_ip, PLC_SERVER_PORT)` | non-blocking; completion seen through `Sn_SR` |
| Socket status register | `getSn_SR(0)` | `SOCK_ESTABLISHED` (0x17) = connected; `SOCK_CLOSED` = failed; checked on every tick in `CONNECTING`, `IDLE`, `AWAITING_RESPONSE` |
| Received byte count | `getSn_RX_RSR(0)` | wait for a whole response; detect an oversized backlog |
| Send / receive | `send()`, `recv()` | one 12-byte request, one 11-byte response |
| Close | `close(0)` | on every failure; abortive (the peer sees an RST, not a FIN) |

`connect()` is a variadic macro in this library revision: a three-argument call
expands to `connect_W5x00()`. It cannot be taken as a function pointer.

## 7.6 Features left unused

| Feature | State | Consequence |
|---|---|---|
| Interrupt output (INTn) | `IMR` and `SIMR` left at their reset value 0x00 (all sources masked); `wizchip_setinterruptmask()` is never called | PB5 never fires. `plc_link_on_exti()` exists so PB5 has an owner in the shared EXTI9_5 handler and an interrupt-driven revision has a starting point. Polling from the main loop is already as prompt as an interrupt would be. |
| Ping block (`MR_PB`) | never set | the device answers ICMP echo; the only way to find it from a host |
| Retry time / count (`RTR`, `RCR`) | chip defaults; `wizchip_settimeout()` is never called | TCP retransmission timing is the W5500's default |
| TCP keep-alive (`Sn_KPALVTR`) | not set | a cable pulled while `IDLE` is noticed only when `Sn_SR` leaves `SOCK_ESTABLISHED`, i.e. after the next request fails or times out |
| Sockets 1–7 | 0 KB buffers | cannot be opened |
| DHCP, DNS and other `Internet/` services | not vendored | static addressing only |

The device opens no listening socket. A port scan finds nothing open; that is
the correct result, not a fault.

## 7.7 Vendored library

`Lib/w5500/ioLibrary/` is WIZnet `ioLibrary_Driver` at commit
`39fae86465dbaa728107c3b2a90692c0a1639735`, `Ethernet/` tree only
(`wizchip_conf`, `socket`, `W5500/w5500`) plus its licence file. Chip and mode
are selected by `PUBLIC` compile definitions in `Lib/w5500/CMakeLists.txt`
(`_WIZCHIP_=W5500`, `_WIZCHIP_IO_MODE_=_WIZCHIP_IO_MODE_SPI_VDM_`), so
consumers see the same register layout as the library. Warnings from the
vendored sources are relaxed; the port is compiled with the project's
warnings.

**Local modification:** in `recv()` (`socket.c`), upstream tested the
non-blocking flag before testing whether data had arrived. Because `SOCK_BUSY`
is 0, a non-blocking socket returned 0 even with a complete frame waiting, and
the link closed a healthy connection after every poll. The two tests are
swapped, matching the order upstream already uses in its IPv6 branch. The
details are in `Lib/w5500/UPSTREAM.md`; re-apply the change when updating the
library.

## 7.8 Troubleshooting the chip

If the device blinks code 3 at start-up, or the link never leaves
`CHIP_FAULT`, `VERSIONR` did not read `0x04`. Check in this order:

1. **MISO and MOSI swapped.** The most common wiring fault. The RJ45 link LEDs
   still light, because the PHY negotiates with the switch on its own as soon
   as the module has power; they prove power and cable, not SPI. The module is
   the slave: its MOSI goes to PB15, its MISO to PB14.
2. **All 0x00 or all 0xFF read back.** SCSn (PB12) not toggling, or the module
   without 3.3 V or a common ground.
3. **No response at all.** RSTn (PA10) stuck low.
4. **Garbled or intermittent.** SPI mode or bit order changed in the `.ioc`,
   or leads too long for 12 Mbit/s (try ÷4).

After start-up, `CHIP_FAULT` retries every `PLC_RECONNECT_DELAY_MS` silently:
the blink code and the fault sound happen once, at `plc_link_init()`. Link
problems above the chip (cable, PLC address, validation) are covered in
[08-modbus-tcp.md](08-modbus-tcp.md#87-diagnosing-the-link) and
[13-build-test-debug.md](13-build-test-debug.md).
