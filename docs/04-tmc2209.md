# 4. TMC2209 stepper driver

This document describes the TMC2209 as this firmware uses it: the module and
its wiring, the single-wire UART, what the firmware writes into the driver at
start-up, which of the driver's many features are active, and how the vendored
library is structured. It is not a datasheet summary; for register details see
the vendor documentation linked at the end.

**Source files:** `App/Src/motion_planner.c` (`motor_driver_init()`,
`initialize_motors()`), `Lib/tmc2209/tmc2209.h`, `Lib/tmc2209/tmc2209.c`,
`Lib/tmc2209/tmc2209_stm32.h`, `Lib/tmc2209/tmc2209_stm32.c`,
`Lib/tmc2209/CMakeLists.txt`.

## 4.1 The module

The prototype uses two BIGTREETECH TMC2209 V1.2 modules (StepStick
footprint, 15.24 × 20.32 mm). Supply range 4.75–28 V on VM, 2 A RMS / 2.8 A
peak per coil.

| J1 pin | Name | Connected to | | J2 pin | Name | Connected to |
|---|---|---|---|---|---|---|
| 1 | EN | ENN GPIO (PA5 / PB0) | | 1 | VM | +12 V |
| 2 | MS1 | GND | | 2 | GND | GND |
| 3 | MS2 | GND | | 3 | A2 | motor coil A |
| 4 | PDN | USART RX direct, USART TX through 1 kΩ | | 4 | A1 | motor coil A |
| 5 | PDN | not connected | | 5 | B1 | motor coil B |
| 6 | CLK | not connected (internal clock) | | 6 | B2 | motor coil B |
| 7 | STEP | STEP timer output (PA1 / PB1) | | 7 | VCC_IO | +3.3 V |
| 8 | DIR | DIR GPIO (PA4 / PA7) | | 8 | GND | GND |

On this module the UART is routed to J1 pin 4 by a factory solder bridge;
moving the bridge selects pin 5 instead. The DIAG, INDEX and VREF pads on the
top edge are not connected.

| Motor | USART | TX / RX | ENN | STEP | DIR |
|---|---|---|---|---|---|
| 01 (disc 1, dots 1 · 4) | USART2 | PA2 / PA3 | PA5 | PA1 (TIM2_CH2) | PA4 |
| 02 (disc 2, dots 2 · 3 · 5 · 6) | USART3 | PB10 / PB11 | PB0 | PB1 (TIM3_CH4) | PA7 |

## 4.2 Single-wire UART

The TMC2209 has one bidirectional UART pin (PDN_UART). The MCU's TX and RX are
both connected to it: RX directly, TX through 1 kΩ so the driver can pull the
line against the MCU's idle-high TX when it answers.

| Property | Value | Set by |
|---|---|---|
| Baud rate | 115200, 8N1 | `MX_USART2_UART_Init()` / `MX_USART3_UART_Init()` |
| Serial address | 0 | `TMC2209_SERIAL_ADDRESS_0`, strapped by MS1 = MS2 = GND |
| Write datagram | 8 bytes (sync, address, register \| 0x80, 4 data, CRC8) | library |
| Read | 4-byte request, 8-byte reply | library |

Because TX and RX share the wire, every byte the MCU sends is received back.
The library waits up to 4 ms (`TMC2209_ECHO_DELAY_MAX_MICROSECONDS`) for the
echo and discards it before reading a reply; a reply is awaited for up to
10 ms (`TMC2209_REPLY_DELAY_MAX_MICROSECONDS`).

Each driver has its own USART, so both can use address 0. Putting both drivers
on one USART would require different MS1/MS2 strapping and a different
`tmc2209_serial_address_t` per driver.

In UART mode MS1/MS2 select the address only. The microstep resolution comes
from the CHOPCONF register (`mstep_reg_select = 1`), so the "MS1 = MS2 = GND
→ 8 microsteps" row of the module's standalone table does not apply here, even
though 8 is also the value the firmware writes.

## 4.3 Configuration written at start-up

`motor_driver_init()` runs once per driver from `initialize_motors()`, while
ENN is high:

1. `tmc2209_stm32_hal_init()` — binds the library to the USART registers and
   the ENN pin, enables the DWT cycle counter.
2. `HAL_Delay(APP_DRIVER_POWER_UP_MS)` — 200 ms before the first datagram.
3. `tmc2209_setup(tmc, &hal, TMC2209_SERIAL_ADDRESS_0)`:
   - GCONF: `pdn_disable = 1` (PDN pin is UART, not power-down),
     `mstep_reg_select = 1` (microsteps from MRES), `i_scale_analog = 0`
     (current reference is internal; VREF is ignored), `multistep_filt = 1`;
   - IHOLD_IRUN, CHOPCONF, PWMCONF, COOLCONF, TPOWERDOWN, TPWMTHRS = 0,
     VACTUAL = 0, TCOOLTHRS, SGTHRS: library defaults;
   - clears drive errors, sets minimum current, disables the driver, and turns
     automatic current scaling and gradient adaptation off.
4. `tmc2209_enable_automatic_current_scaling()` and
   `tmc2209_enable_automatic_gradient_adaptation()` — re-enabled on purpose:
   in stealthChop with automatic scaling off the coils only receive the fixed
   PWM_OFS amplitude and IRUN/IHOLD have no effect, which leaves the motor
   very weak.
5. `tmc2209_set_microsteps_per_step(tmc, APP_MICROSTEPS)` — 8.
6. `tmc2209_set_run_current(tmc, APP_RUN_CURRENT_PERCENT)` and
   `tmc2209_set_hold_current(tmc, APP_HOLD_CURRENT_PERCENT)` — 25 % each.
7. `tmc2209_enable()` — ENN low and CHOPCONF.TOFF restored.
8. Returns `tmc2209_is_setup_and_communicating()`, which reads GCONF back and
   checks `pdn_disable`. A `false` here means no valid reply over UART.

After both drivers, `tmc2209_move_using_step_dir_interface()` writes
VACTUAL = 0 so motion is commanded only by STEP/DIR pulses.

### Resulting operating mode

| Feature | State |
|---|---|
| Interface | STEP/DIR for motion, UART for configuration |
| Chopper | stealthChop (library default; TPWMTHRS = 0 never switches to spreadCycle) |
| Microsteps | 8 per full step, interpolated internally (CHOPCONF.intpol) |
| Current control | internal reference, automatic current scaling |
| Run / hold current | 25 % of full scale each: IRUN = IHOLD = 7, i.e. (7 + 1)/32 |
| StallGuard / coolStep | not used |
| DIAG / INDEX outputs | not used |

The percentage maps linearly onto the 0–31 current scale. The full-scale current
depends on the module's sense resistors (with `vsense = 0`, roughly
`0.325 V / (R_SENSE + 0.02 Ω) / √2`). **The module's VREF potentiometer has no
effect** in this configuration: current is set only through
`APP_RUN_CURRENT_PERCENT` / `APP_HOLD_CURRENT_PERCENT`. Measure coil current
on the real module before raising them.

### Changing the configuration

- **Current:** change `APP_RUN_CURRENT_PERCENT` / `APP_HOLD_CURRENT_PERCENT` in
  `motion_planner.c`. Heat and torque scale with it; the discs need little
  torque.
- **Microsteps:** change `APP_MICROSTEPS`. Every derived constant
  (`APP_MICROSTEPS_PER_REV`, step rates, homing budgets) follows, and the
  angle frame is independent of microstepping. It must stay a value at which
  22.5° is a whole number of microsteps (2 or more), see
  [05-motion-and-homing.md](05-motion-and-homing.md#51-frames-of-reference).
- **Rotation direction** is not set in the driver: the firmware inverts DIR at
  the pin (`APP_MOTOR_DIR_INVERTED`). Leave the driver's `shaft` bit alone.

## 4.4 Failure behaviour

If `tmc2209_is_setup_and_communicating()` returns `false`,
`initialize_motors()` blinks `FAULT_LED_CODE_MOTOR_01` or `FAULT_LED_CODE_MOTOR_02` and continues.
The motor still moves, because STEP/DIR and ENN do not depend on the UART, but
it runs on whatever configuration the driver holds after power-up. In that
state the driver's own defaults apply (standalone mode: microsteps from MS1/MS2,
current from VREF), so motion may be coarse or weak.

Causes, in order of likelihood:

1. TX and RX not both reaching the PDN pin, or the 1 kΩ missing or on the
   wrong line (the MCU must receive its own echo).
2. The module's UART solder bridge moved to J1 pin 5.
3. VCC_IO not powered: the logic side is dead even if VM is present.
4. A different serial address strapped on MS1/MS2.

## 4.5 Library structure

| File | Role |
|---|---|
| `tmc2209.h` / `tmc2209.c` | Portable driver: datagrams, CRC, register shadow copies, the public API. No MCU headers. |
| `tmc2209_stm32.h` / `tmc2209_stm32.c` | STM32 port: fills `tmc2209_hal_t` |

The port's requirements:

- **USART access is register-level.** The port polls `SR.RXNE`/`TXE`/`TC`
  and reads/writes `DR` directly, draining received bytes into a 16-byte ring
  buffer whenever the library asks for available data. No interrupt is used;
  the USART must already be initialised (baud rate, pins) by the HAL.
- **Device header.** The port selects the USART register layout from the
  CMSIS device header named by `TMC2209_STM32_DEVICE_HEADER`, set to
  `"stm32f1xx.h"` in `Lib/tmc2209/CMakeLists.txt`. `tmc2209_stm32.c` also
  includes `stm32f103xb.h` directly; a port to another STM32 family must change
  both.
- **Delays.** Microsecond delays busy-wait on the DWT cycle counter
  (`SystemCoreClock` must be correct). Cortex-M0/M0+ parts fall back to a
  calibrated loop.
- **Enable pin.** ENN is written through `BSRR`, active low.

| Function | Where |
|---|---|

| `tmc2209_setup()` | `motor_driver_init()` |

| `tmc2209_is_setup_and_communicating()` | `motor_driver_init()` |

### API available but unused

| Purpose | Functions | Needs UART read-back |
|---|---|---|
| Direction in the driver | `tmc2209_enable_inverse_motor_direction()`, `tmc2209_disable_inverse_motor_direction()` | no |
| Current in mA | `tmc2209_set_rms_current()`, `tmc2209_set_all_current_values()`, `tmc2209_set_hold_delay()` | no |
| Chopper tuning | `tmc2209_enable_double_edge()`, `tmc2209_enable_vsense()`, `tmc2209_set_pwm_offset()`, `tmc2209_set_pwm_gradient()` | no |
| Power at standstill | `tmc2209_set_standstill_mode()`, `tmc2209_set_power_down_delay()` | no |
| stealthChop / spreadCycle | `tmc2209_enable_stealth_chop()`, `tmc2209_disable_stealth_chop()`, `tmc2209_set_stealth_chop_duration_threshold()` | no |
| Load sensing | `tmc2209_set_stall_guard_threshold()`, `tmc2209_enable_cool_step()`, `tmc2209_get_stall_guard_result()` | yes |
| Internal motion generator | `tmc2209_move_at_velocity()` | no |
| Diagnostics | `tmc2209_get_version()`, `tmc2209_get_status()`, `tmc2209_get_global_status()`, `tmc2209_get_settings()`, `tmc2209_get_microstep_counter()`, `tmc2209_get_interface_transmission_counter()` | yes |

Homing does not use StallGuard: each disc has an optical sensor, which gives a
physical reference independent of load.
